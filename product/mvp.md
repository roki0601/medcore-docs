# MVP

## Цель

Сделать минимальный рабочий сервис, который помогает студенту-медику готовиться к экзамену по одному предмету.

## Основной пользовательский сценарий

1. Пользователь регистрируется или входит в систему.
2. Выбирает предмет.
3. Выбирает раздел и тему.
4. Читает учебный материал.
5. Проходит карточки.
6. Проходит тест.
7. Отмечает тему изученной и/или получает системное завершение по учебной активности.
8. Видит прогресс по теме.

## Что входит в MVP

- Регистрация и авторизация.
- Telegram-аутентификация как основной сценарий.
- Логин + пароль как резервный сценарий.
- Bearer JWT для доступа frontend к backend API.
- API versioning: `/api/v1/...`.
- 1 предмет на старте.
- Структура `Subject → Section → Topic`.
- Slug для пользовательских URL предметов/разделов/тем.
- Необязательные учебные блоки внутри темы.
- Markdown как основной формат учебного текста.
- Карточки.
- Тесты с одним правильным ответом.
- Прогресс по темам.
- Ручная кнопка «Изучено».
- Возможность системно отметить тему завершенной по учебной активности.
- Прогресс по карточкам без FSRS.
- История попыток тестов.
- Поиск через `icontains` по названиям предметов, разделов и тем.
- Django Admin для наполнения и проверки контента.
- Физическое удаление контента с корректными FK-правилами.

## Что пока не входит

- AI-чат для пользователей.
- Голосовой экзамен.
- Сложные рекомендации.
- FSRS.
- Telegram-бот как отдельный продуктовый интерфейс.
- Celery/Redis.
- Elasticsearch/OpenSearch.
- Сложная продуктовая event-аналитика.
- Привязка к конкретному вузу.
- Платежи до первичной проверки спроса.

## Подписки

Монетизация добавляется позже.

Важно: платный доступ не моделируется ролью `premium`.

Роли пользователя (`user`, `editor`, `admin`) отвечают за permissions, а подписка будет отдельной сущностью и будет отвечать за коммерческий доступ.

## Контент MVP

Контент можно добавлять постепенно. У темы не обязаны быть заполнены все блоки, карточки, тесты или источники.

Статусы контента закладываются заранее:

```text
draft → generated → reviewed → published
```

На первом этапе допускается загружать уже проверенный контент сразу как `published`.

Ориентир на первый тест продукта:
- 30–50 качественных тем;
- 15–30 карточек на заполненную тему;
- 10–15 тестовых вопросов на заполненную тему.

Количество не является жестким ограничением БД.

## Проверка гипотезы

После готовности базового продукта дать доступ небольшой группе студентов и смотреть на фактическое использование продукта. Специализированную систему продуктовой event-аналитики можно добавить после появления первых реальных пользователей.
