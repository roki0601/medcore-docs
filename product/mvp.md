# MVP

## Цель

Сделать минимальный рабочий сервис, который помогает студенту-медику готовиться к экзамену по одному предмету.

## Основной пользовательский сценарий

1. Пользователь открывает предмет.
2. Выбирает раздел и тему.
3. Читает учебный материал.
4. Проходит карточки.
5. Проходит тест.
6. Видит прогресс по теме.

## Что входит в MVP

- 1 предмет на старте.
- Структура `Subject → Section → Topic`.
- Необязательные учебные блоки внутри темы.
- Карточки.
- Тесты с одним правильным ответом.
- Прогресс по темам.
- Прогресс по карточкам.
- История попыток тестов.
- Поиск по темам.
- Django Admin для наполнения и проверки контента.

## Что пока не входит

- AI-чат для пользователей.
- Голосовой экзамен.
- Сложные рекомендации.
- FSRS как обязательная часть первой версии.
- Telegram-бот.
- Celery/Redis.
- Привязка к конкретному вузу.
- Платежи до первичной проверки спроса.

## Контент MVP

Контент можно добавлять постепенно. У темы не обязаны быть заполнены все блоки.

Ориентир на первый тест продукта:
- 30–50 качественных тем;
- 15–30 карточек на заполненную тему;
- 10–15 тестовых вопросов на заполненную тему.

Количество не является жестким ограничением БД.

## Проверка гипотезы

После готовности базового продукта дать доступ небольшой группе студентов и измерять фактическое использование: темы, карточки, тесты, возвраты и завершение учебных сессий.
