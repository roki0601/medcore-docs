# ADR 0006: Anonymous demo content before authentication

## Status

Accepted

## Context

Ранее MVP фиксировал, что учебный контент доступен только авторизованным
пользователям. После появления frontend-прототипа и уточнения продуктового
сценария это ограничение пересмотрено.

Нужно дать новому пользователю возможность понять ценность продукта до
регистрации/входа, не открывая при этом полный учебный каталог и персональные
функции.

## Decision

Anonymous user может видеть ограниченный демонстрационный учебный контент до
авторизации.

Допустимые примеры demo-контента:

- пример теории;
- пример карточек;
- при необходимости пример тестового сценария.

Полный учебный контент, полноценная навигация по обучению, персональный
прогресс, сохранённые attempts/reviews и другие user-specific возможности
требуют authentication.

Demo access не отменяет backend-side access control и paywall. Backend обязан
явно различать публичный demo-доступ и обычный authenticated access.

Точная техническая модель demo-контента пока не фиксируется. Отдельная content
feature spec должна определить, используется ли:

- специальный demo/public flag;
- curated demo selection;
- отдельный demo endpoint;
- другая эквивалентная модель.

Coding-agent не должен самостоятельно выбирать один из этих вариантов до
утверждения соответствующей feature spec.

## Consequences

- Пункт 113 в `0004-mvp-decision-register.md` («учебный контент MVP доступен
  только авторизованным пользователям») считается переопределённым этим ADR.
- Frontend может показывать ограниченный demo flow без auth.
- Backend auth/access docs должны разрешать только явно определённый публичный
  demo scope; остальной учебный контент остаётся закрытым.
- Guest demo не создаёт персональный learning state и не сохраняет прогресс как
  пользовательский progress.
